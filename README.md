# 🛒 «Корзинка»: продуктовый дашборд и A/B-тест нового чекаута

Пет-проект BI-аналитика: **Apache Superset + PostgreSQL + Python**.
Данные синтетические, но собраны так, чтобы вести себя как настоящие — с сезонностью, когортами, сбоями и неочевидными эффектами.

## 2. Данные

Период: **2026-05-01 — 2026-08-31**. Схема `raw` в Postgres (база `korzinka`).

| Таблица | Строк | Что внутри |
|---|---|---|
| `raw.users` | 44 000 | `user_id`, `registered_at`, `platform`, `city`, `acquisition_channel` |
| `raw.sessions` | 305 293 | `session_id`, `user_id`, `session_start`, `platform`, `added_to_cart`, `reached_checkout`, `made_order` |
| `raw.orders` | 77 243 | `order_id`, `user_id`, `session_id`, `created_at`, `platform`, `items_cnt`, `amount_rub`, `status` (`delivered` / `cancelled`) |
| `raw.ab_assignments` | 24 419 | `user_id`, `ab_group` (`control` / `test`), `assigned_at` — момент первой сессии в период теста |

Воронка сессии: **визит → корзина → чекаут → заказ**.

⚠️ Данные «как в жизни»: в них есть минимум три вещи, которые испортят выводы, если считать в лоб. Найди их сама — это и есть самая ценная часть проекта.

## 3. Задание

### Часть 1. Дашборд «Здоровье продукта» (Superset)

Минимум:

- **KPI-плитки** за выбранный период: DAU/WAU, число заказов, выручка (GMV), средний чек (AOV), конверсия визит→заказ, доля отмен.
- **Динамика** по дням/неделям: DAU, заказы, выручка.
- **Воронка** визит → корзина → чекаут → заказ (с разбивкой по платформам).
- **Новые пользователи** по каналам привлечения.
- **Когортный retention** по неделе регистрации (тепловая карта).
- **Фильтры**: даты, платформа, город, канал.

Требования к «инженерной» части:

1. Не строй чарты прямо на `raw.*`. Сделай **витрины** в схеме `mart` (SQL-views) — например `mart.daily_metrics`, `mart.funnel_daily`, `mart.cohort_retention`. SQL храни в `sql/`.
2. Метрики (AOV, конверсия) заведи как **metrics** в датасете Superset, а не считай в каждом чарте заново.
3. Каждый чарт должен отвечать на вопрос. Если не можешь сформулировать вопрос — чарт не нужен.

### Часть 2. A/B-тест `checkout_v2`

1. **Дизайн постфактум.** Сформулируй гипотезу, выбери основную метрику, вспомогательные и **guardrail-метрики**. Единица анализа — пользователь. Подумай, какие заказы считать (до или после `assigned_at`?).
2. **Проверки корректности.** SRM (соотношение групп), чистота данных, пересечения.
3. **Оценка.** Эффект + доверительный интервал + p-value. Для конверсий — z-тест / χ², для денег — t-тест Уэлча или бутстрэп.
4. **Глубже.** Срезы (платформа, город), динамика эффекта во времени. Помни про множественные сравнения.
5. **Решение.** Одна страница для Ани: что делаем, почему, какие риски. Никаких «p=0.03, значит хорошо» — переведи в деньги и продукт.

Где делать: расчёты — в Jupyter (`notebooks/ab_test.ipynb`, GitHub рендерит его прямо в браузере), визуализацию результатов — отдельный дашборд в Superset «A/B checkout_v2».

### Часть 3 (бонус). Промо-кампания июля

Сравни пользователей из `promo_july` с другими каналами: retention, частота заказов, выручка на пользователя. «Зашла отлично» — правда?

## 4. Как запустить

Нужен Docker Desktop (Windows/Mac) или Docker + Compose (Linux).

```bash
git clone <твой-репозиторий>
cd korzinka-superset
docker compose up -d --build      # первый запуск ~5–10 минут
```

Открой http://localhost:8088, логин `admin` / пароль `admin`.

**Подключение базы в Superset:** Settings → Database Connections → + Database → PostgreSQL → строка подключения:

```
postgresql://analyst:analyst@analytics-db:5432/korzinka
```

(хост `analytics-db` — имя сервиса в docker-compose, а не `localhost`).

Из DBeaver/DataGrip на своём компьютере: `localhost:5433`, тот же логин.

Пересоздать данные с нуля: `docker compose down -v && docker compose up -d`.
Сгенерировать CSV заново (не обязательно, они уже в `data/`): `pip install -r requirements.txt && python generate_data.py`.

Разминочная витрина, чтобы проверить, что всё работает (выполни в SQL Lab):

```sql
CREATE OR REPLACE VIEW mart.daily_orders AS
SELECT created_at::date AS dt, platform,
       count(*)            AS orders,
       sum(amount_rub)     AS gmv
FROM raw.orders
GROUP BY 1, 2;
```

## 5. Как показать проект на GitHub

Superset — это сервер, на GitHub Pages его не запустить. Поэтому проект публикуется так, чтобы его можно было **увидеть за 30 секунд** и **воспроизвести за 10 минут**:

1. **Скриншоты и GIF** дашборда в `screenshots/` и прямо в README (GIF записывается ScreenToGif / Kap / LICEcap).
2. **Экспорт дашборда:** Dashboards → отметь дашборд → Bulk select → Export. Получишь ZIP с YAML (чарты, датасеты, подключение). Положи в `dashboards/`. Любой сможет импортировать его: Dashboards → Import (иконка загрузки).
3. **Ноутбук с A/B-анализом** — GitHub отрисует его с графиками.
4. **README-витрина**: задача → данные → что нашла → решение → как запустить.

Опционально: PDF-выгрузка дашборда (Download → Export to PDF) или короткое видео на YouTube/Loom со ссылкой в README.
